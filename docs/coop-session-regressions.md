# Co-op session repairs — October 30, 2026

- **Morphing:** local menu documents have a different `performance.now()` origin from the running game. A parent's previous cooldown could therefore appear permanently in the future inside its menu. Morph changes now execute through the parent game's canonical morph/combat modules and clock. Actual recovery restrictions remain, failure reasons appear inside the menu, and successful choices save. Each menu also owns its ability-controller state instead of inheriting the parent's mutable selection state.
- **P2 drop-out/rejoin:** the local menu input filter consumed the two-button drop-out chord before session handling. Drop-out now bypasses that filter and accepts either button order. The explicit local shortcut saves/leaves directly, matching the menu action, without a browser confirmation dialog that cannot be controlled by the pad and freezes the other player. The leaving input cannot also start joining during the same update. Saved profiles remain available for rejoining.
- **Controller identity:** browser hardware indices are no longer treated as player identities. Logical slots first match the live Gamepad object, then reserved device ID/index, and only allocate unclaimed devices to unbound slots. The host controller is reserved when normalizing co-op assignments. A missing host pad does not promote P2's pad. Same-model live objects and distinct-ID reconnect/index changes are covered by tests. When identical pads both disconnect and return as new objects with the same ID, the browser supplies no unique physical identity; simultaneous reconnection still needs a physical hardware check.
- **Fast enemies:** generated continental snapshots saved adjusted speed/attack periods without `fastCombatVersion`. Reloading could apply the tempo multiplier again on each cycle. The marker now persists. Legacy dynamic-patrol snapshots rebuild only tempo from authored kind/tier values, retaining health/reward state and legacy elite speed modifiers. Enemy level scaling and difficulty rules were not changed.

Executed checks:

- `verify-coop-session-regressions.cjs`: actual two-controller join; both players morph through pointer/controller UI with an older parent clock; genuine recovery still rejects changes with feedback; P2 menu drop-out/rejoin with preserved morph; both chord orders while menus are open; hardware-index swap and host disconnection without controller theft; zero page errors or blocking dialogs.
- `verify-coop-session-state.mjs`: device identity/order/disconnection tests, including same-model live objects; 25 generated-patrol save/reload cycles with exactly unchanged speed and attack period; accelerated legacy patrol repaired without healing.
- Existing local-menu, continental-persistence, all 146 optional morphs/438 real casts, XP/revive, Block/fifth-slot, and aim regressions pass. Production build and whitespace checks pass.

Physical controllers and an extended human session remain unverified. Tests use the real browser Gamepad polling path with simulated devices, not physical USB/Bluetooth hardware.
