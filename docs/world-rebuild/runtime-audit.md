# World runtime audit

Pre-rebuild baseline reviewed 8 October 2026 against the PDF's current implementation amendment. See README.md and the verification reports for the delivered continental implementation. The amendment takes precedence over the older architecture wishlist: retain working gameplay, geographic difficulty, resource persistence, final-boss-only portals, and existing playable regions.

Rebuilding or stretching that dense structure across an entire continent is inappropriate. Keep the public world bridge and use a resident chunk adapter. |

## Difficulty findings

No player-level or equipment-based enemy stat matching was found in the reviewed overworld, regional, route, side-zone and dungeon builders. `overworldUtils.getEnemyDefaults` uses explicit area tier; dynamic encounter tier is selected from its geographic site name; dungeon stats use tier and floor depth. Global health/damage tuning is 1.25 with a version marker to prevent stacking. `enemyProgression` derives combat level from enemy level/tier, not player progression.

Co-op intentionally changes enemy population and boss health by active party size, with caps. This is separate from forbidden player progression matching and should remain a deliberate existing co-op contract. Armour reduces incoming damage during combat; that mitigation is not enemy stat scaling. Exact geographic level ranges should be assigned in continental definitions, including legacy regional enemies whose high HP currently coexist with default tier-derived level metadata.

Recommended regression: instantiate the same authored geographic encounter with level 1, 60 and 200 players and very different equipment; assert identical enemy ID, base/combat level, tier, HP, damage, XP and loot profile under the same seed and party size.

## Recommended continuous continent architecture

Retain the Canvas2D renderer, absolute pixel coordinates, tile collision, player movement and combat contracts. At the proposed ~100,000px extent, JavaScript double precision comfortably represents subpixel movement. Canvas drawing already subtracts camera origin. A floating-origin rewrite has no demonstrated benefit here.

Use a single continental definition containing authored polygons, rivers, road splines and named stable anchors. Geographic identity must remain independent of `actId`; acts describe story progress. Resident gameplay chunks expose a bounded set of terrain/collision data and entities, while a global small metadata index holds quest/NPC/dungeon/Nav Stone anchors.

Materialize terrain and collision first, then structures/nearby actors, decoration and ambience. Use rings based on the union of live party positions, viewport and velocity lookahead. Cache the recently departed ring with hysteresis; pin combat participants and transition destination until safe. Use ordinary broadphase buckets for interaction, projectiles and collision; no global route-graph or distant-world simulation replacement is needed initially. Regions can have lightweight authored patrol schedules, but unseen AI must not run full combat.

The compatibility tile view must be side-effect-free for save serialization. A direct `JSON.stringify(world.tiles)` must never materialize the whole continent. Public save and transition paths must explicitly exclude it. Width / height should come from world metadata first. Renderer cache and resident chunk counts require separate measured caps and developer counters.

Persist gameplay mutations by stable entity ID: dead/removed or wounded enemy, already-rolled loot flags, reward claim, event state and remaining-expiry ground drops. Continue the existing harvest clock and region-specific keys. No default scenery, pristine HP, authored arrays or generated tile data belongs in the save. Hydration reapplies state before entities become targetable. Unloading does not count as death, does not reroll a pack, and does not advance a respawn cycle. Expiry pruning may remove expired transient drops/resources; it must not arbitrarily truncate permanent quest or reward state.

## Migration risks and tests

1. **Duplicate entities / rewards:** traverse 100+ chunk seams and return. Assert uniqueness by stable ID, no duplicate XP/loot, wounded HP unchanged and killed enemies remain gone until an explicitly configured population reset.
2. **Resource rerolls:** harvest, cross eviction boundary, save/reload before expiry; assert same node ID/position, still depleted, same remaining timer. Preserve legacy `overworld:hearthmereFrontier:*`, `overworld:aureateMarches:*` and `overworld:ascensionWastes:*` keys through relocation.
3. **Portal migration:** enter every migrated dungeon from its actual surface entrance, save while inside, defeat only final main boss, save/reload again, return. Assert exactly one portal and actor-radius collision-safe arrival near that entrance, facing south. Preserve parallel gate / side-room entrances separately by entrance ID.
4. **Legacy saves:** fixture schema16 saves in each region, travel route, town, dungeon and side zone. Check one-time coordinate translation; reload the resulting schema17 save twice and ensure positions do not shift again. Quest flags, inventory copy upgrades, known skills, morphs, co-op profile metadata and boss first-kill rewards must be identical.
5. **Nav travel:** distant attuned target unloaded; hydrate destination before collision / danger validation. Test unsafe target, depleted ration, missing party, companion down and recent combat; no cost debit on failure, exactly one debit on success.
6. **Long-traversal performance:** record frame-time p50/p95/p99, resident chunks, cached ground canvases, active enemies, tree buckets and heap at start / mid-route / finish / repeated return. Memory should plateau after cache warmup. No global scenery arrays should increase with distance walked.
7. **Collision seam:** actor + projectile + summon cross diagonally at max movement / charge speed; confirm water/cliff barriers, bridges, stairs, forest trunks and camera edge bounds. Tile lookup outside a resident chunk must preload or safely stop movement rather than teleport actor to a distant default spawn.
8. **Gameplay camera QA:** screenshots at real approach points and normal zoom across city gate, farmland, river bridge, forest opening, ridge, Veyr courtyard, mine entrance, Marches and Wastes. Landmarks must guide navigation without covering the player/telegraphs; player fades never change collision.

Existing useful verification scripts: `verify-world-overhaul.mjs`, `verify-echoryn.mjs`, `verify-echoryn-followers.mjs`, `verify-orrakai.mjs`, `verify-dungeon-return-portals.mjs`, `verify-dungeon-map-return.cjs`, `verify-dungeon-floor-progression.mjs`, and browser world-review tools. Their fixed original world-count assertions will need conversion to stable-content and chunk-residency contracts, not deletion.

## Coordinated implementation responsibility

The root agent owns continental geometry/streaming, hub integration and common gameplay hooks. This audit agent owns `continentPersistence.js`, schema17 save metadata/migration and the sparse continental dungeon/side-zone/tower return paths. No combat balance or second encounter framework is introduced by this work.

## Verified integration

- `verify-continent-persistence.mjs` passes: 2,000 pristine scenery objects produce no saved entity records; 100 hydration cycles retain enemy identity/death; actual distant chunk unload/revisit preserves wounded HP; destination preview does not rewind fresh damage; picked-up/expired drops cannot reappear; inactive capture cannot refresh resource/drop expiry; temporary snapshots cap at 64, retain a nearby overdue fight, and expire after leaving; legacy regional coordinates translate once; emergency quota fallback retains entry identity. The representative sparse surface save is 7,832 bytes.
- `verify-continent-instance-returns.mjs` passes with actual retained early side-zone/tower entrances. A virtual tile view throws on iteration/serialization, proving entries do not clone surface geography. Side-zone killed enemies, claimed chests and clear state survive active expedition reload without duplicate clear XP. Tower floor advancement/reload retains floor and surface entry. Both return to nearby actor-safe space facing south.
- Existing `verify-dungeon-return-portals.mjs` passes all seven themes: final main boss alone unlocks one reachable portal; minibosses/floor guardians/extra bosses cannot unlock it; surviving ordinary enemies do not prevent exit; victory portal and actual entrance return persist through saves.

Side-zone geometry remains generated per new expedition, as before, while an expedition in progress now saves its finite instance state. Completed first-clear rewards remain under the existing host-player side-zone records. Surface saves continue to exclude geometry and decorative arrays.
